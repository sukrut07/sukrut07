# Contributing Guidelines

Thank you for considering contributing to **sukrut07**! We welcome community contributions, bug fixes, documentation improvements, and feature suggestions.

## Code of Conduct

Please review and adhere to our [Code of Conduct](CODE_OF_CONDUCT.md) in all community interactions.

## How to Contribute

### 1. Reporting Issues
- Check existing issues before opening a new one.
- Provide a clear and descriptive title along with steps to reproduce if reporting a bug.

### 2. Submitting Pull Requests
1. Fork the repository.
2. Create a topic branch: `git checkout -b feature/your-feature-name`.
3. Make your changes adhering to existing code formatting.
4. Commit your changes with clear, descriptive commit messages:
   ```bash
   git commit -m "feat: add feature description"
   ```
5. Push to your branch: `git push origin feature/your-feature-name`.
6. Open a Pull Request against the `main` branch.

## Commit Message Convention
- `feat`: A new feature or addition.
- `fix`: A bug fix or patch.
- `docs`: Documentation updates.
- `refactor`: Code refactoring without functionality changes.
- `style`: Formatting or whitespace fixes.

## Co-Authoring Commits
If collaborating with another contributor, please include co-author attribution in your commit message footer:
```text
Co-authored-by: Name <email@example.com>
```

Thank you for contributing! 🚀
